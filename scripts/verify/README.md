# 界面与链路的客观验证脚本

这里放的是**不能靠肉眼判断的东西**的自动化验证。CLAUDE.md 第九节要求：
「我无法截图，肉眼也不是可靠的证据」，所以每一阶段结束时都要跑这些脚本。

## 怎么跑

```bash
# 1. 先构建生产版本
npm run build

# 2. 逐个跑（每个脚本自己会启动 Electron、跑完自己关掉）
env -u ELECTRON_RUN_AS_NODE node "scripts/verify/检查数据库读写链路.mjs"
env -u ELECTRON_RUN_AS_NODE node "scripts/verify/检查分类管理界面.mjs"
env -u ELECTRON_RUN_AS_NODE node "scripts/verify/检查记账页.mjs"
env -u ELECTRON_RUN_AS_NODE node "scripts/verify/检查账单页.mjs"
env -u ELECTRON_RUN_AS_NODE node "scripts/verify/检查统计页.mjs"
```

**跑之前先把残留的 Electron 关掉**（`taskkill //F //IM electron.exe`）。
上一次没退干净的进程会占着数据库文件，脚本第一步清空隔离目录就会报 `EPERM, Permission denied`。

**调试端口每个脚本一段，别改回都用 9222。** 每个脚本顶部有 `BASE_PORT`
（9222 / 9232 / 9242 / 9252 / 9262），脚本内每启动一次 Electron 再 `nextPort()` 往后挪一个。
原因见下面「已知的坑」最后一条——五个脚本共用 9222 会让串行跑出现无规律的假失败。

**脚本碰不到你的账本。** 每个脚本都用 `--user-data-dir` 把 Electron 的数据目录挪到
`<项目>/.verify-data/<脚本名>/`，启动前先清空那里面。`%APPDATA%\HTJizhang`
（你账本所在）一个字节都不会被读写——见 CLAUDE.md §九。**别把 `--user-data-dir` 改掉。**

`env -u ELECTRON_RUN_AS_NODE` **不能省**：本机环境设了这个变量，会导致 Electron
退化成普通 Node、不弹窗口也不建渲染进程，脚本会一直等到超时。

脚本跑完会打印 `结果：N/M 项通过`。有失败项时退出码为 1。

## 用户实际是怎么打开软件的？

**这是最容易漏掉的一环。** 第 2 阶段所有端到端验证都直接跑 `npm run dev` 或构建产物，
从没真正双击过 `启动HT记账.bat`——而用户用的是后者，于是「.bat 因行尾是 LF 而静默失效」
这个 bug 一路漏到了用户面前，现象是「双击了没反应」。

所以：**改了启动方式、改了 .bat、改了打包配置之后，要用用户的方式真走一遍。**

## 两个必须守住的规矩

1. **脚本自己要做反向辨识验证。** 改坏一处功能，确认对应的检查项**确实会失败**——
   否则你分不清「检测通过」和「检测根本没在看」。本项目已经这样做过多次，
   在提交信息里都有记录。
2. **脚本全在隔离目录里跑，你不需要手动清库。** 每个脚本启动前自己清空
   `<项目>/.verify-data/<脚本名>/`（就是它通过 `--user-data-dir` 交给 Electron 的那个目录），
   所以「首次启动」这类检查每次都成立。
   **脚本不读、不写、不删 `%APPDATA%\HTJizhang`（你账本所在）。**
   2026-10-04 之前它们确实直接用真实目录、账单页脚本还会 `rmSync` 清空它——
   那时用户还没开始记账，没造成损失；第 4 阶段收尾改成了隔离目录。
   **往后再加验证脚本，一律照抄这个做法。**

## 已知的坑（CLAUDE.md §9 有完整版）

- 点击后必须等一帧。带 `transition-colors` 的元素要等过 150ms，否则读到的是过渡中间态。
- **要验证「鼠标移上去才出现」的效果，必须用 CDP 的 `Input.dispatchMouseEvent`
  真把指针移过去**（`检查账单页.mjs` 里的 `hover()` 辅助函数），再等过过渡时长（用 320ms）
  读 `getComputedStyle(el).opacity`。
  **不能**用 JS 派发 `mouseover` 或手动加类名——CSS 的 `:hover` 只认真实指针位置，
  伪造出来的事件改不了它，检查会变成空转（「通过」了但什么都没看）。
  另外：`opacity: 0` 的元素**仍然可以被 `.click()` 点到**，所以「藏起来」和「点不到」
  是两回事，别把两者混为一谈。
- `innerText` 在弹性布局里会把图标和文字拆成两行，比较前先归一化空白。
- Tailwind v4 输出 `oklch()` 色彩空间，不是 `rgb()`。
  判断红/绿**别去比 rgb**，改读 `getComputedStyle(el).color` 里的**色相**（`oklch` 的第三个数）：
  红在 22 度附近、绿在 152 度附近，差别很大；明暗主题会改亮度和彩度，但不会改色相。
- 不要用「注入子元素」判断节点是否被卸载——React 会清掉它不认识的多余节点，会误报。
- **`data-testid` 不能跨页面重名，弹窗里的尤其容易撞。** 四个页面是常驻挂载的
  （见 `App.tsx`），所以任何新弹窗里出现的输入框，只要复用了记账页的组件并沿用默认标识，
  文档里就会同时存在两个同名元素：`querySelector` 会抓到记账页那个（还藏在 `hidden` 里），
  脚本会以为自己在验证弹窗。`AmountInput` / `PaymentMethodPicker` 现在都能传
  `testId` / `testIdPrefix`，弹窗传 `edit-*`。`CategoryPicker` 的 `pick-*` 因为到处都在用，
  改不了名字，只能在 `edit-dialog` 子树里找（`window.__T.inScope`）。
- **取值的方法要能容忍元素不存在。** 标识一旦写错，`one(...).textContent` 会直接抛错、
  中止整个脚本，后面还没跑的检查项全被遮住——你看到的是一行报错，而不是「哪几项失败了」。
  所以用 `window.__T.text/val/attr/disabled` 这些取不到就返回 `null` 的方法。
- **隔离目录之后，`app.setName` 的效果测不到了。** 2026-10-04 实测：把
  `src/main/index.ts` 顶部的 `app.setName('HTJizhang')` 注释掉，在隔离目录下
  **所有检查照常通过**——因为 `--user-data-dir=X` 直接定死了 userData，跟程序名无关。
  所以 §5.16 那个「数据目录漂移」缺陷，验证脚本**不再覆盖**。
  收尾时我先加了一条「没有多出 `Electron` 子目录」的检查，被反向辨识证明是**空转的**
  （注释掉 `setName` 它照样绿），已删除。这条缺陷现在只靠 `src/main/index.ts` 里
  那行代码的**位置**保证——**改那个文件顶部时要格外小心**。
- **`count()` 只按 `data-testid` 找，找 CSS 选择器要用 `svg()`。** 第 5 阶段实测踩到：
  `window.__T.count('path.recharts-sector')` 查的是 `[data-testid="path.recharts-sector"]`，
  **永远返回 0**，于是「没有支出时饼图不画扇区」这条检查*一直通过*——它从头到尾没在
  看饼图。这就是 CLAUDE.md §九 说的「分不清『检测通过』和『检测根本没在看』」。
  找 DOM/CSS 一律用 `svg(selector)`（`document.querySelectorAll` 的裸查询）。
  **新写取值辅助函数后，先用一个必然失败的选择器试它一次**，确认它真的会报错而不是静默返回 0。
- **色相判据要给一个区间，不能只给下界。** 判断「这个数字是不是绿的」写成 `hue > 120`，
  **会把中性灰也算成绿** —— Tailwind 的 slate 系是蓝灰，色相 255~257，比绿(152)还大。
  实测（2026-10-04）：把结余改成灰色之后，`hue > 120` 这条检查照样通过。
  正确写法是 `hue > 100 && hue < 200`。
  **改任何颜色断言之后，都要把颜色真的改错一次，看它红不红。**
- **Recharts 3.10 的两个脾气**（第 5 阶段实测）：
  1. **零高度的柱子不渲染**（`Rectangle` 返回 `null`）。所以柱子数 = **有数据的月份数**，
     不是 12。别写「应该有 12 根柱」这种断言。要防「整根图错位」，用**柱子与横轴刻度的
     对齐**来查：取每根柱子的中心 x，找最近的刻度，比对应有的月份序号。
  2. **横轴的刻度文字挂在 `<svg>` 根节点下，不在 `.recharts-xAxis` 里面**。
     `'.recharts-xAxis text'` 取到 0 个。要用 `.recharts-surface text` 再按 `/月$/` 过滤
     （纵轴的纯数字标签自然被排除）。刻度那行 `<g class="recharts-cartesian-axis-tick">`
     是空的，拿它算位置会得到 `0x0`；用文字的 `getBBox()`。
  3. 容器尺寸塌成 0（页面被 `hidden`）时它**会卸载整个 `<svg>`**，恢复尺寸后再挂回来。
     所以切页之后要 `waitStable()` 等 DOM 稳定，别立刻读数。
- **五个脚本原先都用调试端口 9222，串起来跑会出无规律的假失败。** 2026-10-04 实测：
  一次串行跑全量时账单页报 95/96，单独重跑 9 遍全是 96/96，怎么都复现不出来。
  机制：脚本内部会重启 Electron（`child.kill()` 后只睡 1.5 秒就再 spawn），
  Windows 上子进程这时还没真消失，而实测**新实例在端口被占时照样打印
  「DevTools listening on 9222」并成功启动**——两个进程共存，
  `http://localhost:9222/json/list` 这次答的是谁完全不确定。
  现在每个脚本一段专属端口（9222/9232/9242/9252/9262）、脚本内每次启动再 +1，
  脚本之间和脚本内部都不会撞。
  **注意：这只是消除一个已确认的脆弱点，不是「修好了那次失败」**——那次失败没能复现，
  机制是推断出来的，不是抓住的。
